## Working style preferences

- **Quality over quantity**: one correct PR > five mediocre ones.
- **Understand before touching**: reads code, traces execution paths before proposing changes.
- **uv over pip**: always. Never suggest pip as primary tool.
- **No unsolicited cleanup**: PEP8, typos, docstring reformatting are out of scope.

## What to avoid

- Don't summarize what you just did — they can read the diff.
- Don't manufacture work or pad issue queues — only verified, real bugs.
- Rank work by impact, not size. (Superseded 2026-08-29: the research-team phase that reserved beginner-tier issues for students ended in June 2026.)
