Refs #2236. #2698 left the Three.js half for its own PR.

`Graphics3d` gets a `_repr_html_()` that returns the scene in an `<iframe srcdoc>`, so a plain Python kernel shows the interactive viewer instead of a static PNG. The page builder moves out of `_rich_repr_threejs()` into a new `_render_html_()` that returns the HTML document, and the old method stays on top as the `OutputSceneThreejs` wrapper. `save('foo.html')` calls `_render_html_()` too, and still needs passagemath-repl unless called with `online=True`. `show()` is untouched at `base.pyx:1989-1991` and still calls `display_immediately` with no fallback, so `sphere()` displays in Colab and `sphere().show()` does not.

`_repr_html_()` forces `online=True`, even on an object built with `online=False`. Finding a local three.js copy is a display backend's job, and a plain kernel either has no backend or gets the commandline one, which answers with a filesystem path a remote notebook cannot fetch. The `online=True` branch of `threejs_scripts()` needs no backend either, so it moves to `Threejs.cdn_scripts()`, which `DisplayManager` now calls.

The iframe carries no `sandbox` attribute, matching the copies in `backend_ipython` and `backend_marimo`. A sandboxed copy renders the same scene, but `sandbox` blocks the viewer's Save as PNG and Save as HTML without `allow-downloads`, so all three copies should change together.

Doctests in `plot3d/base.pyx` go from 430 to 440 under `--optional=sage,sage.symbolic`, all passing. `sage -t` cannot reach the no-repl path, so a tox check renders a sphere with `sys.modules["sage.repl"] = None`; on the unpatched build it fails with `AttributeError: 'sage.plot.plot3d.shapes.Sphere' object has no attribute '_repr_html_'`. That check needs no `!notest` gate, unlike the `_repr_png_` one above it, which needs Tachyon from the test extra. On the stock `python3` kernel, whose first cell prints `IPython.core.formatters.DisplayFormatter`, the gyroid comes back as `['image/png', 'text/html', 'text/plain']` and renders from the HTML.

Diff mechanics: the 143-line body of `_rich_repr_threejs()` moves into `_render_html_()` unchanged except for two lines becoming seven at the script tag and two becoming one at the return, and the docstring did not move with it. The header, INPUT, OUTPUT and EXAMPLES are written fresh for `_render_html_()`, and `_rich_repr_threejs()` gets a new wrapper docstring. Only the TESTS block carried over, with `._rich_repr_threejs(online=True).html.get_str()` rewritten to `._render_html_(online=True)`.
