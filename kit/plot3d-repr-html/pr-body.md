Refs #2236. #2698 left the Three.js half for its own PR, after #2351 and #2366 did the 2D case.

`Graphics3d._repr_html_()` returns the scene in an `<iframe srcdoc>`, so plain Python kernels get the interactive viewer instead of a static PNG. The renderer moves out of `_rich_repr_threejs()` into `_render_html_(**kwds)`, which returns the HTML document, and `_rich_repr_threejs()` becomes the `OutputSceneThreejs` wrapper on top. `_render_html_()` still imports the display manager on its `online=False` branch, so `save('foo.html')` loses the container round-trip but keeps needing passagemath-repl unless called with `online=True`, which is what its doctest does.

`_repr_html_()` loads three.js from the CDN even when the object carries `online=False`, because an offline copy resolves through a display backend, a plain kernel has none, and the commandline backend answers with a local path a remote notebook cannot fetch. The `online=True` branch of `threejs_scripts()` needs no backend either, so it moves to `Threejs.cdn_scripts()` and `DisplayManager` delegates to it. The iframe carries no `sandbox`, like the copies already in `backend_ipython` and `backend_marimo`, so the CDN script keeps parent-page authority. That exposure is inherited rather than added here, and sandboxing belongs in one change across all three, because the viewer's Save as PNG and Save as HTML items are script-initiated downloads that a sandbox blocks without `allow-downloads`.

406 to 416 doctests in `plot3d/base.pyx`, all passing. `sage -t` cannot reach the no-repl path, so a tox check renders a sphere with `sys.modules["sage.repl"] = None`; on the unpatched build it fails with `AttributeError: ... no attribute '_repr_html_'`. The screenshot is a notebook on the stock `python3` kernel whose first cell asserts `IPython.core.formatters.DisplayFormatter`: the gyroid comes back as `['image/png', 'text/html', 'text/plain']` and renders from the HTML. `show()` is untouched and still calls `display_immediately` with no fallback (`base.pyx:1989-1991`), so `sphere()` will display in Colab and `sphere().show()` will not.
